# 자녀 증여자산 시뮬레이터 — 2단계 기획 (신뢰·플래닝·전환)

작성일: 2026-08-03
선행 문서: `2026-08-02-child-finance-simulator-design.md` (1단계 설계)
브랜치: `feature/child-finance-simulator` → `staging`

## 0. 확정된 사용자 결정 (2026-08-03)

- **우선순위**: 신뢰 보강 → 플래닝 강화 → 전환 동선 완성. 세 축 모두 진행.
- **기존 증여**: "가정 명시"에 그치지 않고 **선택 입력으로 받아 합산**한다.
- **결과 아래 연결**: **무료 가이드 2편만** 연결한다. ManualPromo(유료 매뉴얼 티저)는
  도구 페이지에 넣지 않는다 — 도구의 중립성 유지. 매뉴얼 전환은 가이드 글 안의
  기존 ManualPromo가 담당한다.

## 1. 진단 — 1단계는 "계산기"로는 완성, "제품"으로는 미완

| 층위 | 문제 | 결과 |
|---|---|---|
| 신뢰 | 10년 합산 공제를 무시하고 "첫 증여"를 암묵 가정 | 이미 증여한 적 있는 핵심 타깃에게 틀린 "한도 이내" 판정 |
| 가치 | "조건 → 결과" 단방향. 부모의 실제 질문은 "세금 없이 월 얼마까지?" | 가장 궁금한 질문에 답을 안 줌 |
| 동선 | 설계가 명시한 유입 장치 미구현, 계약서 핸드오프 무피드백 | 계산 후 흐름이 끊김 |

## 2. A축 — 신뢰 보강: 기존 증여 선택 입력

### A1. 입력

- 위치: **자세히 설정** 안 (기본 조건을 늘리지 않는다 — 처음 온 사용자 대부분은 해당 없음)
- 필드: "최근 10년 내 이 아이에게 증여한 금액" — `AmountInput` 재사용, 기본 0(빈칸)
- 도움말: "부모(같은 증여자 그룹)가 이미 증여해 신고했거나 할 예정인 금액입니다."
- 검증: 0 이상, 12자리 제한 (AmountInput 기본 동작)

### A2. 계산 반영 — 공제 한도 차감까지만 (1차)

- `judgeDeduction()`에 기존 증여액 파라미터 추가:
  `available = max(0, limit − priorGifts)`, `excess = max(0, valuation − available)`
- 상증세법 §53의 공제 한도는 10년 합산 기준이므로 이 차감은 법령 그대로다.
- **과세표준 합산(§47③)과 기납부세액공제는 1차에서 반영하지 않는다.** 기존 증여의
  과세표준·납부세액까지 받으면 입력 부담이 커지고 검증 필요 지점이 늘어난다.
  화면에 "기존 증여의 세액 합산·기납부세액공제는 반영하지 않습니다"를 명시한다.
- ⚠️ **세무사 검수 항목**: 한도 차감 방식과 "세액 합산 미반영" 단순화가 오해를
  만들지 않는지. (검수 전 배포 금지 아님 — 단순화 명시로 충분한지가 검수 대상)
  특히 **기존 증여가 한도를 초과하는 입력에서 과세최저한(§55②)으로 "세금 0원" 판정이
  나오는 케이스** — 실제 통산 과세표준은 50만 원을 넘을 수 있어 단정 판정이 위험한지 확인
  (코드 리뷰 지적, 2026-08-03).

### A3. 표시

- 기존 증여 입력이 있으면 공제 한도 판정 줄에 반영을 드러낸다:
  "한도 이내 (₩20,000,000 중 기존 증여 ₩5,000,000 차감 후 ₩15,000,000 기준)"
- 입력이 없으면(0) **단순화 가정에 전제를 명시**한다:
  "최근 10년 내 같은 증여자에게 받은 다른 증여가 없다고 가정합니다.
  있다면 '자세히 설정'에 입력하세요."

## 3. B축 — 플래닝 강화: 한도 내 최대액 안내

### B1. 원칙 검토 (선을 넘지 않는 근거)

"세금 없이 주려면 월 얼마까지?"는 **세법 산술**이지 투자 판단이 아니다.
상품 선택·수익률 가정과 무관하게 공제 한도와 유기정기금 평가 규약만으로 정해진다.
1단계 원칙 "계산만 하고 판단하지 않는다"와 충돌하지 않으며, 유료 매뉴얼의 핵심
(아동수당 비과세 관리, 계좌 운용 판단, 늦은 신고 수습)을 침범하지 않는다 —
공개 법령 정보의 산술 적용이다.

### B2. 동작

- **유기정기금**: 현재 조건(시작일·기간·지급일·기존 증여 차감 후 한도)에서
  평가액이 한도와 같아지는 **최대 월 증여액**을 이분탐색으로 역산한다.
  `solveTarget.ts`의 이분탐색 패턴 재사용. 평가액은 월액에 단조증가라 수렴 보장.
- **일시금**: 역산 불필요 — 차감 후 한도 금액 그대로.
- 원 단위 절사(내림). 한도를 1원이라도 넘는 값을 안내하면 안 된다.

### B3. UI

- 위치: 공제 한도 판정 바로 아래 (판정과 같은 맥락에서 읽히도록)
- 문구: "이 조건에서는 월 ₩166,000까지 한도 이내입니다" + **[이 금액 적용]** 버튼
- 적용 버튼은 매월 증여액 입력값을 바꾸는 것뿐 — 추천·권유 아님(금액은 세법이 정한다)
- 이미 한도 이내면: 현재 입력과 한도 최대액을 같이 보여준다 (여유분 인지)
- 목표 역산 모드에서는 표시하지 않는다 (목표가 우선인 화면에 정보 과다)

## 4. C축 — 전환 동선 완성

### C1. 계약서 핸드오프 피드백 (버그에 가까운 UX 결함)

- `App.tsx`의 복원 안내(`showRestored`)가 draft에만 반응하고 시뮬레이터 핸드오프에는
  침묵한다. 핸드오프 감지 시 Step 1 상단에 안내:
  "시뮬레이터에서 계산한 조건(월 ₩200,000 · 2026-09-01~2036-08-31)을 가져왔어요.
  인적사항만 입력하면 됩니다."
- 1단계 설계 §5.2의 "Step2가 채워진 상태로 시작"은 **Step 1 시작 + 안내**로 확정
  변경한다. 인적사항 없이 Step 2부터 시작하면 뒤로 돌아가야 해서 오히려 마찰.

### C2. 관련 가이드 연결

- 위치: 단순화 가정 아래, 계약서 CTA 위
- 기존 `related-guides` + `guide-card` 패턴 재사용, **2편 고정**:
  1. 유기정기금 증여 신고 가이드 (`/guide/annuity-gift-report`) — 계산 다음 행동이 신고
  2. 미성년 자녀 주식계좌 가이드 (`/guide/minor-stock-account`) — "그래서 어디에 담지?"의 무료 범위 답
- ManualPromo는 넣지 않는다 (§0 사용자 결정)

## 5. 1단계 설계 문서와 달라진 현행 (문서 현행화 기록)

1단계 문서를 기준으로 작업하면 역행하는 항목들. 코드가 아니라 문서가 낡았다.

| 1단계 문서 | 현행 구현 | 판단 |
|---|---|---|
| 수익률 빈칸 + placeholder | 기본값 `0` | 현행 유지 — 빈칸은 진입 즉시 에러 상태를 만들고, 0은 "수익 제시"가 아님 |
| 수익률 범위 ±20% | ±30% | 현행 유지 — 나스닥 '최근까지' 22.1% 칩 수용 |
| 참고 수익률: 접힌 표 | 기준 토글(급등 제외/최근까지) + 입력 옆 칩 | 현행 유지 — 출처·경고는 접힘 유지 |
| 결과: 세로 카드 3장 | dl 요약 + 가로 스크롤 상세 표(첫 열 고정) | 현행 유지 |
| 인출 시점 19세 고정 | 조건 파생 기본값(만질 때까지 자동) | 현행 유지 |
| 도메인 검증 메시지 노출 | 화면 용어 `validateForm` 우선, 도메인은 안전망 | 현행 유지 |

## 6. 구현 순서와 검증

1. **C1 핸드오프 안내** — 독립적이고 작음. 즉시.
2. **C2 가이드 연결** — 독립적. 즉시.
3. **A축 기존 증여** — 도메인(`judgeDeduction` 확장 + 테스트) → UI → 가정 문구 동기화.
4. **B축 한도 내 최대액** — A축 완료 후 (차감 후 한도 기준이므로 의존).

- 각 단계: `npm test` 전체 통과 + 모바일(375px) 스크린샷 실화면 확인.
- 도메인 변경은 TDD — `annuity.test.ts` 픽스처 수정 금지 원칙 그대로.
- 세무사 검수 항목 (§2 A2): 기존 증여 한도 차감 + 세액 합산 미반영 단순화의 타당성.

## 7. 이번 단계에서도 하지 않는 것

- 기존 증여의 과세표준 합산·기납부세액공제 (입력 부담·검증 부담 대비 효익 낮음)
- 연금저축계좌·개별 주식 (1단계 문서의 2·3단계 로드맵 그대로 후순위)
- 환율 계산, 종합과세 계산, 분할 매도 (1단계 비목표 유지)
- 도구 페이지 내 유료 매뉴얼 홍보 (§0 사용자 결정)
