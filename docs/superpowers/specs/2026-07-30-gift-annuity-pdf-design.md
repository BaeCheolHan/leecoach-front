# 유기정기금 증여계약서·평가명세서 PDF 생성 서비스 — 설계

날짜: 2026-07-30
상태: 승인 대기

## 목적

미성년 자녀 등에게 정기 현금증여(유기정기금)를 할 때 필요한 두 가지 서류를
웹에서 작성하고 각각 PDF로 내려받아 **홈택스 증여세 신고 시 증빙으로 바로 첨부**할 수 있게 한다.

1. 유기정기금 현금증여계약서 (도장 자동 생성 포함)
2. 유기정기금 평가명세서 (연도별 할인평가 표 + 근거 조문)

참고 구현: https://portfolio.ezinit.com/giftofcash (우동호 유기정기금 계약서 생성기)

## 범위

### 포함
- 증여자/수증자 인적사항, 증여내용(기간·주기·금액·계좌) 입력 폼
- 상증세법 시행령 §62 제1호 유기정기금 할인평가 계산
- 증여재산공제 한도 판정(관계 + 만 나이 기준) 및 예상 증여세 0원/초과 표시
- 성명 기반 도장 이미지 자동 생성
- PDF 2종 개별 다운로드 (+ "모두 다운로드")
- 입력 데이터 localStorage 저장(주민등록번호 제외)

### 제외 (향후 과제로 기록만)
- 국세청 법정 신고서 서식(증여세 과세표준신고 및 자진납부계산서 등) 재현
- 홈택스 화면 입력 보조(입력 순서대로 값 나열) 화면
- 10년 내 기증여 합산 입력
- 엑셀 출력
- 회원가입/서버 저장
- 산출세액 계산(공제 한도 판정까지만)

## 아키텍처

**서버 사이드 코드 없음.** React 정적 SPA. 모든 계산과 PDF 생성은 브라우저에서 수행한다.

- 호스팅: Oracle Cloud Free Tier `VM.Standard.E2.1.Micro`(x86, 1GB RAM) + nginx 정적 서빙 + Let's Encrypt TLS
  - Ampere A1(ARM, 24GB)은 용량 부족으로 생성 불가한 상태라 저스펙 x86을 사용.
    정적 서빙만 하므로 1GB로 충분(nginx 상주 10~20MB).
  - 배포: `vite build` 산출물 rsync
- 개인정보(주민등록번호)는 네트워크로 전송되지 않는다. 이것이 클라이언트 생성 방식을 택한 핵심 근거.

### 스택
- React + TypeScript + Vite
- 폼: react-hook-form + zod
- PDF: `@react-pdf/renderer` (한글 폰트 `Font.register`로 임베딩)
- 도장: canvas 2D → PNG → PDF 삽입
- 테스트: vitest

### 모듈 구조

```
src/
  domain/annuity/    유기정기금 할인평가 — 순수 함수, 의존성 0
  domain/giftTax/    공제 한도 판정(관계·만 나이) — 순수 함수, 의존성 0
  pdf/contract/      증여계약서 PDF 문서
  pdf/schedule/      평가명세서 PDF 문서
  pdf/seal/          성명 → 도장 PNG 생성
  ui/                3단계 스텝 폼 + 결과 화면
  storage/           localStorage 어댑터(주민번호 제외 직렬화)
```

계산부(domain/*)는 UI·PDF에서 완전히 분리한다. 서비스 가치가 숫자 정확성에 있으므로
단위 테스트로 고정하고, UI는 검증된 입력만 계산부에 전달한다(계산부 내부 throw 없음).

### 알려진 제약
- **한글 폰트 용량**: 이름·주소는 임의 글자이므로 사전 서브셋 불가. KS X 1001 2350자
  수준 폰트(~1.5MB)를 PDF 생성 시점에 지연 로딩. 첫 화면 로딩에는 미포함.
  PDF 임베딩 시에는 서브셋되어 파일당 수백 KB 유지(홈택스 첨부 용량 고려).
- **도장 서체**: 자유 라이선스 한글 전서체 부재 → 궁서 계열로 대체(인감 느낌 수준).

## 계산 규칙 (참고 사이트 역산으로 검증됨)

근거: 상증세법 시행령 제62조 제1호, 시행규칙 이자율 연 3%.

```
연도별 평가액 = round( 해당 역년 불입액 합계 ÷ 1.03ⁿ )
n = 해당 역년 − 시작 역년   (첫 해 n=0, 무할인)
총 평가액 = Σ 연도별 평가액   (단, 1년분 정기금액의 20배 상한)
```

- **역년(1/1~12/31) 단위 절단**: 3월 시작이면 첫 해는 10개월치, 마지막 해는 잔여 월수.
- **불입 횟수**: 지급일(매월 n일)이 증여기간 내에 드는 횟수를 역년별로 센다.
- **반올림**: 연도별 표시는 원 단위 반올림. 합계는 **비반올림 연도별 값의 합을 최종 1회 반올림**
  (구현 중 시나리오 2 실측으로 확인 — 반올림값 합산 시 10,492,150으로 1원 어긋남).
  따라서 표의 연도별 값 합과 합계가 ±1원 차이날 수 있으며 이는 참고 구현과 동일한 동작.
- **할인율 3%는 설정값으로 분리**(시행규칙 개정 이력 있음. 상수 하드코딩 금지).
- **미성년 판정: 생년월일 기준 만 19세 미만** (증여개시일 현재, 최초 1회 판정).
  참고 사이트의 연 나이(출생연도+19) 방식과 다르다 — 사용자 결정 사항.
  생일 경계(±수개월)에 걸리는 경우 화면에 안내 문구 표시.

## 공제 한도 판정

- 관계 + 만 나이로 한도 자동 결정: 직계존속→미성년 2,000만 / 성년 5,000만,
  배우자 6억, 기타친족 1,000만 등.
- 결과 화면 표시: `할인평가액 합계 ○○원 / 공제한도 ○○원 → 한도 내(예상 증여세 0원)`
  또는 `한도 초과 ○○원`.
- 고정 경고 문구: 10년 내 동일인 기증여 합산됨(입력 기능은 범위 외),
  신고 책임은 납세자 본인에게 있음(면책). 화면과 PDF 양쪽에 표기.

## 화면 흐름

3단계 스텝 (모바일 우선):
1. 인적사항 — 증여자/수증자 성명·주민번호·주소·연락처, 관계 선택
2. 증여내용 — 시작일·종료일·증여방법·매월 지급일·매월 증여액·입금계좌
3. 결과 — 평가명세서 표 + 공제 판정 + 다운로드 버튼 2개 + "모두 다운로드"

- 단계 이동 시 zod 검증. 주민번호는 형식 + 체크섬(2020-10 이후 출생은 형식만),
  시작일 < 종료일, 10년 초과 기간 경고, 금액 > 0.
- localStorage 자동 저장/복원. **주민등록번호는 저장 대상에서 제외**(재입력 부담이
  낮고 공용 PC 잔존 위험이 큼).

## PDF 산출물 (파일 2개, 개별 다운로드)

홈택스 첨부는 건별 업로드이므로 합본하지 않는다.

1. `증여계약서_수증자명_YYYYMMDD.pdf` — 전문, 조항(증여 내용·지급 방법·계좌),
   당사자 표시(성명·주민번호·주소), 작성일, 도장 이미지
2. `유기정기금평가명세서_수증자명_YYYYMMDD.pdf` — 입력 요약(당사자·관계·기간·할인율),
   연도별 표(년도/불입년도/불입횟수/불입원금/할인평가액), 합계, 근거 조문(시행령 §62),
   면책 문구

도장: 입력 성명을 원형 테두리 안에 배치(2·3·4자 배치 규칙), canvas로 그려 PNG 삽입.

## 에러 처리

- 입력 검증은 전부 폼 단계에서 zod로 차단. 계산부는 검증된 입력만 받으므로 throw 없음.
- PDF 생성 실패(폰트 로딩 실패 등) 시 사용자에게 재시도 안내 토스트.
- 오프라인 폰트 로딩 실패 대비: 폰트는 자체 호스팅(외부 CDN 미사용).

## 테스트

- domain/*: vitest 단위 테스트. 위 픽스처 2건과 원 단위까지 일치해야 함 + 추가 케이스.
- pdf/*: 생성 성공 여부와 페이지 수만 검증(픽셀 비교는 비용 대비 가치 낮음).
- ui: 스텝 이동·검증 메시지 위주의 최소한의 컴포넌트 테스트.

## 미해결 리스크

- **만 나이 vs 연 나이**: 세무 실무 관행과 다를 수 있음. 세무사 검토 전까지
  경계 케이스에 안내 문구로 방어. (참고 사이트는 연 나이 방식)
- 20배 상한·기증여 합산 등 세부 케이스의 법령 해석은 서비스가 자문하지 않음 —
  면책 문구로 고지.
